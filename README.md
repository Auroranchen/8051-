# 8051-
8051八位数字时钟，学校课设项目，估计很多学校也做课设，现在我把它完全开源下来
项目简介
本项目是一款基于 8051 单片机的八位数码管数字时钟。程序使用 Keil C51 编写，工程目标器件配置为 Atmel AT89C52，配套 Proteus ISIS 仿真工程。
源码实现了时钟计时、八位数码管动态扫描、按键设置、三组闹钟、蜂鸣器提示和 60 秒倒计时等功能。仓库同时保留了 Keil 工程文件、Proteus 仿真文件、HEX 固件以及历史构建产物，适合用于学习 8051 定时器、数码管动态显示、按键扫描和单片机工程开发流程。

支持设置小时、分钟和秒；

软件架构
主循环
主循环主要完成以下工作：
根据当前模式更新显示缓冲区；
扫描并处理按键；
根据当前时间和闹钟状态控制蜂鸣器；
执行约 100 ms 的循环延时。
主要函数包括：
`Display()`：组织八位数码管显示内容和设置项闪烁状态；
`Scankey()`：完成按键扫描、消抖及参数修改；
`Write_Duan()`：向段码锁存器输出数据；
`Write_Wei1()`：向位选锁存器输出数据；
`ET0_T0()`：Timer0 中断服务函数。
数码管动态扫描
程序通过两个 74HC573 分别锁存段码和位选数据。Timer0 中断中依次完成：
关闭当前显示；
输出段码；
产生段码锁存脉冲；
输出位选数据；
产生位选锁存脉冲；
切换到下一位数码管。
八位数码管快速轮流点亮，利用视觉暂留形成完整显示。
Timer0 计时
源码使用以下参数重装 Timer0：
TH0 = (65536 - 4000) >> 8;
TL0 = (65536 - 4000) & 0xff;
程序通过累计中断次数推进秒、分、时和倒计时变量。Timer0 中断同时负责数码管动态扫描、倒计时递减和时间进位。
注意：按照标准 12T 8051、24 MHz 晶振估算，上述重装值对应的单次中断周期约为 2 ms，而程序累计 250 次中断后增加 1 秒，理论累计时间约为 500 ms。因此软件计时基准可能存在偏快问题。实际结果还会受到单片机型号、晶振频率、Timer0 模式和 Proteus 配置影响，使用前应通过实测重新校准。
蜂鸣器逻辑
当当前时间的小时、分钟与任意一组闹钟相同时，且秒数小于 5，程序会翻转蜂鸣器控制信号进行提示。
程序还包含以下预提醒逻辑：
每小时 59:50 ～ 59:59
蜂鸣器的有效电平取决于原理图中的驱动方式以及实际使用的有源或无源蜂鸣器，移植到实物时需要重新确认。

Keil 编译方法
安装 Keil uVision 5 和 C51/PK51 工具链；
打开工程文件：
   `text
   程序/程序.uvproj
   `
确认目标器件为 `AT89C52`；
确认工程时钟配置为 `24 MHz`；
执行 `Build` 或 `Rebuild Target 1`；
编译完成后生成：
   `text
   程序/程序.hex
   `
目录中已有的构建日志和链接映射文件显示，曾经有一次构建生成了 HEX 文件，且记录为 0 个错误、0 个警告。该信息属于已有历史构建记录，本次未在当前环境重新编译。

仿真与 Keil 工程的配置差异
当前 Keil 工程与 Proteus 文件存在需要核对的差异：
Keil 工程目标器件为 `AT89C52`；
Keil 工程时钟配置为 `24 MHz`；
Proteus 文件中可识别到 `AT89C51/AT89C52` 相关模型信息；
Proteus 文件中可识别到 `12 MHz` 时钟设置；

已知限制
时间和闹钟参数保存在 RAM 中，断电后不会保存；
未使用独立 RTC 芯片，实际走时精度需要校准；
工程依赖 24 MHz 时钟配置，更换晶振后需要重新计算 Timer0 参数；
倒计时功能固定为 60 秒，不能自定义、暂停或取消；
按键采用轮询和阻塞式延时，长按不支持连续调节；
闹钟没有独立启用/禁用、消音和持久化功能；
蜂鸣器输出频率依赖程序时序和硬件类型，不能视为精确音调；
源码集中在单个 `main.c` 文件中，尚未拆分为独立模块；
源码和日志中存在旧路径、历史项目名称及编码问题；
Proteus 文件与 Keil 工程存在型号、时钟和路径差异，需要人工核对；
当前目录没有发现正式 README、BOM、实物照片、测试记录或许可证文件。
